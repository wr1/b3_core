## Choice table

| Backend | Strengths | Limits |
|---------|-----------|--------|
| **`mfem`** (**default**) | Fast in-process; isotropic **and** orthotropic + per-GP resin halo; datasheet / deformed / viz | Needs PyMFEM |
| **`ccx`** | CalculiX `.inp` + VTU post; validation twin | Isotropic two-phase; needs `ccx` + `frd2vtu` |
| **`fenicsx`** | Optional high-order FEM research path | Extra install; isotropic two-phase |
| **`numpy`** | Fallback RVE path; always available | Analytical / semi-analytical |

```yaml
# omit backend → mfem
backend: mfem
validate_with_ccx: true   # optional cross-check vs CalculiX
```

## Auto-routing

`auto` prefers **`mfem`**, which now covers every constitutive map:

1. **orthotropic** `core` / `resin` → per-Gauss-point 6×6 stiffness and a
   rotated/mixed `Bᵀ C B` element matrix, or
2. `core.cell_size` set (resin halo) → graded Gauss-point stiffness
   `P·C_resin + (1−P)·C_foam` sampled from the ScoreField. Halo + curvature
   still work — open/close morphs the mesh, then ScoreField grades off `hw(z)`
   ([composition](/docs/concepts/halo-curvature)).

If mfem is not installed the pipeline falls back to the next capable backend,
then `numpy`. ccx and fenicsx integrators remain isotropic two-phase.

## MFEM path (default)

Solves the six periodic unit-strain problems **in-process** (PyMFEM). Isotropic
constituents use MFEM's native `ElasticityIntegrator`; orthotropic constituents
and the graded halo use a per-Gauss-point stiffness with a custom integrator
(same constitutive map as numpy, matching to ~1e-6). Used when `backend` is
omitted or set to `mfem`. Also preferred for:

- `b3_core viz datasheet`
- `b3_core viz deformed`
- interactive `CoreModel` stiffness / displacement fields

No external solver binary. PyMFEM is a required dependency (`uv sync`).

## CalculiX path

1. Build VTS mesh with phase tags.
2. Write six `.inp` decks (C3D8 or C3D20) with periodic `*equation` BC and strain nodes.
3. Run `ccx` in a process pool.
4. Convert FRD → VTU (`frd2vtu`), average face jumps and reactions.

Requires `ccx` and `frd2vtu` on PATH. Set `backend: ccx` explicitly.

## Validation against ccx

```yaml
backend: mfem
validate_with_ccx: true
```

Runs the chosen backend and a CalculiX twin, then records relative differences
in the run JSON. Use when changing mesh density (`madd`) or element type.

## Element types (ccx)

| `element_type` | Notes |
|----------------|-------|
| `C3D8` | Default linear hex |
| `C3D20` | Quadratic hex — slower, smoother fields |
